# instagram-tracker

## 릴스 24시간 판정 (`hit_watch.js`)

수집(`Instagram Tracking`)이 끝날 때마다 이어서 돈다. 인스타그램 API는 부르지 않고 노션만 읽고 쓴다.

1. 노션 '브랜드 action'의 우리 릴스를 읽는다.
2. 게시 20시간이 지난 릴스를 **히트 / 평소**로 판정해 노션 '히트 판정' DB에 1행을 만든다.
   도달이 이미 평소의 2배를 넘었으면 20시간 전이라도 바로 히트로 판정한다.
3. 히트면 디스코드로 알린다. '평소'였던 릴스가 7일 안에 뒤늦게 2배를 넘어도 알린다.
4. 게시 4일 뒤 '3일 팔로워 증감', 7일 뒤 '7일 도달'을 같은 행에 채운다.

| 기준 | 값 |
| --- | --- |
| 히트 | 도달 ÷ 기준 중앙값 ≥ 2, 또는 공유 ÷ 도달 ≥ 0.6% (도달 3,000 이상일 때) |
| 기준 중앙값 | 그 릴스 게시 전 30일 우리 릴스 도달의 중앙값. 도달 1,000 미만은 빼고, 4개 미만이면 60 → 90일 |
| 기록만 하는 기준 | 평균 시청 12초 이상 |

숫자는 출발값이다. `hit_watch.js` 맨 위 `RULES`에서 고친다.

### 설정

- 저장소 Secrets에 `DISCORD_WEBHOOK_URL`을 넣으면 알림이 간다. 없으면 노션에만 기록한다.
- `NOTION_TOKEN`, `NOTION_DB_ID`는 수집 스크립트와 같은 값을 쓴다.
- 노션 '히트 판정' DB에 이 통합이 연결돼 있어야 한다. 못 읽으면 실행이 실패하고 로그에 이유가 나온다.

### 확인

- Actions → `Hit Watch (24h 판정)` → Run workflow → `dry_run`에 `1`: 노션·디스코드에 쓰지 않고 무엇을 할지만 로그로 보여 준다.
- 로컬 테스트: `node --test test/hit_watch.test.js test/hit_watch.run.test.js` (네트워크를 쓰지 않는다)

이 저장소는 공개라서 Actions 로그도 공개된다. 스크립트는 기본 로그에 도달·공유 같은 숫자와 캡션을 찍지 않는다.
